# 2026-04-08 서버 초기 패키지 및 Docker 설정 정리

## 문서 목적
- Oracle Cloud Ubuntu 20.04 ARM64 서버에서 현재 프로젝트를 진행하기 위해 실제로 설치한 패키지와 그 이유를 기록한다.
- 다른 팀원이 정리해 둔 초기 세팅 방법 중 현재 서버 환경과 맞지 않는 부분을 바로잡는다.

## 현재 서버 전제
- OS: Ubuntu 20.04.6 LTS (Focal)
- 아키텍처: ARM64 (`aarch64`)
- 사용자: `ubuntu`
- 권한: `sudo` 비밀번호 없이 가능 (`NOPASSWD: ALL`)

## 이미 실행한 명령
```bash
sudo apt-get update
sudo apt-get install -y git ca-certificates curl gnupg nginx certbot python3-certbot-nginx
sudo apt-get install -y docker.io
```

## 패키지별 설치 이유
### `git`
- 프로젝트 소스를 clone, pull 하기 위해 필요하다.
- 배포 이론상 배포 대상 코드를 서버에 동기화하는 가장 기본 도구다.

### `ca-certificates`
- HTTPS 통신 시 서버 인증서를 검증하기 위한 루트 인증서 묶음이다.
- 외부 저장소, GitHub, Docker 이미지 다운로드 등 거의 모든 네트워크 작업의 기반이 된다.

### `curl`
- URL 기반으로 파일이나 응답을 받아오는 도구다.
- 설치 키 다운로드, 헬스체크, API 점검에 자주 사용된다.

### `gnupg`
- GPG 키를 다루는 도구다.
- 외부 apt 저장소를 등록할 때 패키지 서명 검증용 키를 처리할 때 필요하다.

### `nginx`
- 외부 80/443 요청을 받아 내부 컨테이너로 전달하는 Reverse Proxy 역할을 한다.
- 나중에 SSL 종료 지점과 Blue/Green 전환 지점이 된다.

### `certbot`
- SSL 인증서 발급 및 갱신 도구다.
- HTTPS를 적용하기 위해 필요하다.

### `python3-certbot-nginx`
- Certbot이 Nginx 설정과 연동할 수 있게 해주는 플러그인이다.
- Nginx 설정 자동 반영 또는 nginx 기반 인증서 발급에 사용된다.

### `docker.io`
- Ubuntu 저장소에서 제공하는 Docker Engine 패키지다.
- 현재 서버에서 컨테이너 기반 배포를 시작하기 위한 핵심 런타임이다.

## 다른 팀원 정리 내용에서 수정이 필요한 부분

### 1. `docker.io` 설치 후 Docker 공식 `focal` repo를 다시 추가하는 흐름
이 부분은 지금 기준으로 권장하지 않는다.

이유:
- Docker 공식 Ubuntu 설치 문서는 2026-04-08 기준 지원 OS로 `22.04`, `24.04`, `25.10`, `26.04`를 안내한다.
- 즉 `20.04`는 Docker 공식 apt repo 기준 지원 목록에 없다.
- 따라서 이미 `docker.io`를 설치한 상태에서 다시 Docker 공식 `focal` repo를 섞어 쓰는 것은 구조가 어정쩡해진다.
- 또한 Docker 공식 문서는 `docker.io`, `containerd`, `runc` 같은 배포판 패키지를 Docker 공식 패키지와 섞지 않도록 주의시킨다.

정리:
- 지금 서버에서는 `docker.io` 기반으로 가는 것이 더 일관적이다.
- 즉 `docker.io`를 유지한다면 Docker Compose도 Ubuntu 쪽 패키지 흐름으로 맞추는 편이 낫다.

### 2. Compose v2를 위해 Docker 공식 repo를 추가하는 단계
현재 Ubuntu 20.04 ARM64에서는 굳이 이 경로로 갈 필요가 없다.

이유:
- Ubuntu Focal(20.04)에는 `docker-compose-v2` 패키지가 별도로 제공된다.
- 이 패키지는 `docker.io`와 맞물려 `docker compose` 명령을 사용할 수 있게 해준다.
- 따라서 지금 환경에서는 `docker-compose-v2`를 Ubuntu 저장소에서 설치하는 방법이 가장 단순하고 일관적이다.

### 3. Certbot 설치 방식
현재는 `apt`로 `certbot`, `python3-certbot-nginx`를 설치했다.

참고:
- Certbot 공식 사이트는 Ubuntu + Nginx 기준으로 요즘은 `snap` 설치를 우선 안내한다.
- 하지만 현재처럼 이미 apt 패키지로 설치해 학습용 서버를 진행하는 것은 충분히 가능하다.
- 중요한 것은 apt 버전과 snap 버전을 섞지 않는 것이다.

정리:
- 지금은 apt 기반 certbot을 유지해도 된다.
- 나중에 certbot 관련 이상 동작이 있거나 최신 공식 흐름으로 완전히 맞추고 싶다면 snap 전환을 검토한다.

## 현재 서버에서 더 정확한 Docker / Compose 설정 방법
### 1. Docker 서비스 활성화
```bash
sudo systemctl enable --now docker
```

### 2. 버전 확인
```bash
docker --version
```

### 3. 현재 사용자를 docker 그룹에 추가
```bash
sudo usermod -aG docker ubuntu
```

### 4. 새 그룹 반영
둘 중 하나:
```bash
newgrp docker
```
또는 SSH 재접속

### 5. 그룹 반영 확인
```bash
groups
```
출력에 `docker`가 보여야 한다.

### 6. 동작 테스트
```bash
docker run --rm hello-world
```

### 7. Compose v2 설치
현재 서버에 더 맞는 방법:
```bash
sudo apt-get update
sudo apt-get install -y docker-compose-v2
```

### 8. Compose 확인
```bash
docker compose version
```

## 지금 서버에서 권장하는 최종 순서
```bash
# 1) 기본 패키지 준비
sudo apt-get update
sudo apt-get install -y git ca-certificates curl gnupg nginx certbot python3-certbot-nginx

# 2) Docker 설치 (Ubuntu repo)
sudo apt-get install -y docker.io
sudo systemctl enable --now docker

# 3) 현재 사용자 docker 그룹 추가
sudo usermod -aG docker ubuntu

# 4) Compose v2 설치 (Ubuntu repo)
sudo apt-get update
sudo apt-get install -y docker-compose-v2

# 5) 새 그룹 반영
newgrp docker

# 6) 확인
docker --version
docker compose version
docker run --rm hello-world
```

## 왜 이 순서가 지금 가장 타당한가
- 현재 서버는 Ubuntu 20.04 ARM64다.
- Docker 공식 apt repo는 현재 기준으로 20.04를 지원 OS 목록에 두지 않는다.
- 반면 Ubuntu 저장소에는 `docker.io`와 `docker-compose-v2`가 존재한다.
- 따라서 지금 서버에서는 "Ubuntu 저장소 기반 Docker + Ubuntu 저장소 기반 Compose"가 가장 일관적이다.
- 이 방식은 최신 Docker CE 정석과는 다르지만, 현재 서버 조건에서는 가장 안정적인 현실적 선택이다.

## 참고한 자료
- Docker Engine Ubuntu 설치 문서: 공식 지원 OS 목록 확인
- Docker Compose Linux 설치 문서: plugin 설치 방식 확인
- Ubuntu Focal `docker-compose-v2` 패키지 정보 확인
- Certbot Ubuntu + Nginx 설치 문서: snap 우선 안내 확인
